# 智学伴第二阶段五人垂直功能分工

## 1. 文档目的

本轮目标是完成一个可模拟上线、可完整演示的智学伴系统。分工采用“垂直功能切片”方式，不按前端、后端或用户端、管理员端拆分。

每名成员独立负责一个业务功能的完整闭环：

```text
用户端页面 + 管理员端页面 + 后端接口 + 数据库调整 + 测试用例
```

本文件是本轮分工依据。此前按技术层或旧业务域划分的任务，仅作为历史参考；如与本文件冲突，以本文件为准。

## 2. 全员共同要求

- 每人必须提交可运行的页面代码、接口代码和测试代码，不能只提交设计稿或数据库表。
- 自己负责的功能必须同时覆盖用户端和管理员端；如果某一侧确实没有页面需求，也要提供对应的数据查询、权限或审计能力。
- 当前用户必须从 JWT 获取，不能信任前端传入的 `user_id`。
- 所有写操作要考虑重复提交、异常回滚和错误提示。
- 新增字段、接口和枚举必须先写入《智学伴第二阶段开发契约与协作规范.md》或在群内确认。
- 不随意大范围重写 `frontend/src/App.vue`、公共路由、统一请求封装和 `backend/main.py`。
- 每个人先完成自己功能的最小闭环，再做视觉优化和扩展功能。

## 3. 成员一：账号、用户与权限

### 3.1 功能目标

负责系统中“谁可以登录、谁可以操作、用户信息如何管理”的完整闭环。

### 3.2 用户端

- 注册、登录、退出登录。
- 登录状态恢复和 Token 失效处理。
- 个人资料查看与修改。
- 用户账号被禁用后的提示和拦截。
- 用户端基础账号测试页面或状态展示。

### 3.3 管理员端

- 管理员登录页。
- 管理员和普通用户角色识别。
- 用户列表、搜索、筛选和分页。
- 用户详情，包括基础资料、学习摘要和账号状态。
- 禁用用户、恢复用户。
- 管理员查看自己的操作记录。

### 3.4 后端与数据

- 管理员认证和权限依赖。
- 用户状态、角色或管理员账号相关字段。
- 用户管理 API 和操作审计 API。
- 保护所有 `/admin/*` 接口，普通用户访问必须返回 403。
- 登录、退出、禁用、恢复等关键操作写入日志。

### 3.5 交付与验收

- 管理员可以登录并查看用户。
- 被禁用的普通用户无法继续访问需要登录的业务接口。
- 普通用户无法读取或修改其他用户数据。
- 用户登录、资料修改、管理员禁用/恢复均有测试。
- 提供固定的管理员演示账号说明，但密码不得写入生产配置。

## 4. 成员二：学情、掌握度与运营看板

### 4.1 功能目标

负责“用户看到自己的学习状态，管理员看到系统整体运营状态”的完整闭环。

### 4.2 用户端

- 学情诊断结果展示。
- 知识点掌握度列表和状态标签。
- 掌握度趋势。
- 首页学习概览或学情摘要。
- 学科、知识点和时间范围筛选。

### 4.3 管理员端

- 运营首页统计卡片。
- 总用户数、活跃用户数、新增用户数。
- 练习次数、完成率、平均正确率。
- 错题数量、复习完成率和掌握度分布。
- 学科趋势、近 7 天/30 天趋势。
- 空数据、加载失败和时间范围切换状态。

### 4.4 后端与数据

- 学情摘要、掌握度和趋势查询接口。
- 管理员统计接口，只返回聚合数据，不泄露不必要的用户隐私。
- 统一活跃行为和学习行为的统计口径。
- 明确“活跃用户”“完成练习”“掌握知识点”等指标的计算规则。

### 4.5 交付与验收

- 用户完成一次学习后，自己的掌握度或学习摘要发生变化。
- 管理员看板能读取真实业务数据。
- 用户数据与管理员聚合数据的统计口径一致。
- 对空数据、时间范围、分页和权限场景提供测试。

## 5. 成员三：题目、练习与题库管理

### 5.1 功能目标

负责“用户使用题目学习，管理员维护题目内容”的完整闭环。

### 5.2 用户端

- 练习列表或推荐练习入口。
- 开始练习、查看题目、提交答案。
- 查看答题结果、正确答案和基础解析。
- 生成题目失败、超时和内容格式异常时的降级提示。
- 防止重复提交答案。

### 5.3 管理员端

- 题目列表、搜索、分页和筛选。
- 按学科、知识点、难度和审核状态筛选。
- 新增、编辑、删除题目。
- 题目审核、上架和下架。
- 查看题目被使用次数、正确率等基础数据。

### 5.4 后端与数据

- 题目、选项、答案、解析、难度和知识点关联。
- 练习组、练习题和答题提交接口。
- 题目状态和审核状态。
- 答题记录必须保存到后续错题、掌握度和统计功能可读取的位置。

### 5.5 交付与验收

- 用户能完成一组练习并看到结构化结果。
- 管理员修改题目后，新的练习能使用更新后的内容。
- 下架题目不再进入新练习，但历史记录仍可查看。
- 题目新增、编辑、审核、答题和重复提交均有测试。

## 6. 成员四：错题、复习与学习报告

### 6.1 功能目标

负责“用户产生学习结果并复盘，管理员查看用户学习质量”的完整闭环。用户端已有功能以联调、修 Bug 和补接口为主，不要求无理由重做。

### 6.2 用户端

- 错题列表、筛选和详情。
- 错题订正和订正结果。
- 知识点复习卡。
- 快速、完整、进阶复习模式。
- 复习进度和完成状态。
- 阶段性学习报告。
- AI 生成失败时使用可用的降级复习内容。

### 6.3 管理员端

- 查看用户错题数量、主要错因和订正率。
- 查看复习完成率和到期复习情况。
- 查看用户薄弱知识点。
- 查看单个用户的学习轨迹摘要。

### 6.4 后端与数据

- 错题、订正、复习记录和报告查询接口。
- 错题与题目、用户、知识点之间的关联。
- 订正成功后掌握度、复习计划和学习记录的更新。
- 管理员只能查看，涉及用户数据修改时必须有明确的运营操作和审计记录。

### 6.5 交付与验收

- 用户答错后能看到错题，订正后状态正确更新。
- 完成复习后，复习记录和报告数据能够更新。
- 管理员查看的数据与用户实际学习记录一致。
- 完成完整用户流程联调，并修复现有用户端小 Bug。

## 7. 成员五：VIP、订单运营、模拟数据与系统集成

### 7.1 功能目标

负责“用户购买权益、管理员运营订单、系统最终可演示”的完整闭环。

### 7.2 用户端

- VIP 介绍和权益展示。
- 创建订单、跳转支付宝沙箱。
- 支付中、支付成功、支付失败、订单关闭等状态展示。
- 订单列表和订单详情。
- VIP 到期时间、使用次数和权益状态。

### 7.3 管理员端

- 订单列表、搜索、分页和状态筛选。
- 订单详情和支付流水信息。
- 待支付、支付中、已支付、关闭和失败订单展示。
- 测试环境下的订单补偿或演示操作。
- 系统日志和异常日志查看。

### 7.4 后端与数据

- VIP、订单、支付查询、支付通知和权益校验接口。
- 订单幂等、支付金额校验和重复通知处理。
- 管理员订单运营接口和审计记录。
- 支付异常不能错误开通 VIP。

### 7.5 模拟数据

统一负责以下脚本，不由其他成员重复编写：

```text
backend/scripts/seed_demo_data.py
backend/scripts/reset_demo_data.py
```

模拟数据包括：

- 演示管理员和普通用户。
- 学科、知识点和题目。
- 最近 30 天登录、练习、错题、复习和报告数据。
- 待支付、支付中、已支付、关闭和失败订单。
- 通知、系统日志和管理员操作日志。

所有模拟数据必须带 `is_demo` 或 `simulation_batch_id` 标识，支持清理和重复生成。

### 7.6 集成与交付

- 负责全系统接口联调和跨模块问题修复。
- 负责处理接口响应、字段、权限和路由冲突。
- 负责合并前检查、启动检查、前端构建和演示环境检查。
- 负责最终演示脚本和全链路验收记录。

## 8. 成员交付清单

每名成员提交时必须包含：

```text
1. 用户端页面或用户端接口变更
2. 管理员端页面或管理员端接口变更
3. 后端 Router / Schema / Service / DAO / Model 中实际需要的代码
4. 数据库迁移或初始化说明
5. 本模块测试用例
6. 接口使用说明
7. 验收步骤和已知问题
```

## 9. 最终演示闭环

```text
普通用户登录
→ 完成诊断
→ 做题
→ 产生错题
→ 完成复习
→ 查看报告
→ 创建/完成 VIP 订单
→ 管理员登录
→ 查看用户、学习统计、题目、错题、订单和日志
→ 验证运营数据随用户操作变化
```

只有用户端产生的数据能被管理员端正确查看，五个功能模块才算完成。
